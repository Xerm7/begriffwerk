# Begriffwerk — German IT Fachbegriffe trainer

**Android APK:** `releases/Begriffwerk-1.0.2.apk` is the latest signed offline Android application, with a native Java/SQLite learning service replacing the previous two-WebView engine. Copy it to your phone and open it to install over version 1.0.0 or 1.0.1. See [current Android architecture and tests](android/README-native.md). Desktop and phone histories are independent.

A complete local learning application using **Node.js 24+, native SQLite, and a separate HTML/CSS/JavaScript frontend communicating over REST**. No npm dependencies, external fonts, cloud services, AI-generated definitions, or accounts. This stack was selected because Node 24 is available locally and provides SQLite without native dependency installation. Python/React are not required.

## Start in this folder

```powershell
cd in project dir
node --version
npm start
```

Open **http://localhost:8000**. Node must be version 24 or later. There are no dependencies to install, so `npm install` is unnecessary. On a different machine install Node.js 24+ first, copy this project and the JSON files, and run the same commands.

The backend initializes `data/learning.sqlite` and imports the JSON files automatically at every startup. Stop with Ctrl+C. Restarting preserves learning progress, sessions, question choices and answer history. The browser stores only a session ID to resume the current session; learning data lives in SQLite.

## Import your files

Leave the supplied JSON files in the project root, or set `DATA_DIR` to another directory containing them. Each matching document must contain `titel`, `thema`, and `bereiche` with section `id`, `titel`, and `fachbegriffe` containing `fachbegriff` and `bedeutung` strings. All JSON documents with this shape in the selected directory are imported; unrelated JSON objects are ignored. Import is not recursive. Malformed JSON or malformed dataset records fail the import with a diagnostic, and the transaction rolls back.

```powershell
npm run import
# Optional alternate source directory:
$env:DATA_DIR='C:\path\to\json'
npm start
```

The supplied dataset imports **13 files, 104 sections, 1,443 occurrences, 1,442 unique exact pairs**. One exact pair belongs to multiple sections and shares one progress record. Strings are stored verbatim; hashes use the exact term and definition. Metadata counts are descriptive only; actual entries determine totals. No wording is edited and no external content is consulted.

Repeated imports preserve progress and do not create duplicate pairs or memberships. Imports are deliberately additive: removing a source file or changing wording does not erase old learning records. A changed pair becomes a new record. Restart the running server after importing additional data so its catalog refreshes. Use a new `DB_PATH` if you intentionally need a fresh independent collection; preserve the original database as a backup.

Production assets (no transpilation or bundling needed):

```powershell
npm run build
$env:FRONTEND_DIR='dist'
npm start
```

Configuration: `PORT` (8000), `DB_PATH` (`data/learning.sqlite`), `DATA_DIR` (project root), `FRONTEND_DIR` (`frontend`). Run commands from the project root. The server binds only to `127.0.0.1`. This is a personal local application; network deployment would need authentication, HTTPS and multi-user ownership.

## How learning works

Every question randomly chooses either term → definition (`a`) or definition → term (`b`), independently of previous directions. The server selects five other dataset entries, excludes duplicate option text and known equivalent pairs, then shuffles all six answers. Each choice has an opaque random token. The question response does not expose the correct token, target ID, or correctness flags. Submission validates the token against the stored question. Duplicate submissions are rejected inside a transaction, preventing double counting.

Distractors favor the same subsection, then the same subject area, then shared words from the original text, with random variation. Answers may come from outside the active filter: filters constrain the **target**, while distractors use the full dataset to preserve six distinct choices even in small subsets. There is no generated answer wording.

Smart Learning first chooses among available priority bands (overdue, weak, learning, new, review, mastered), then uses weighted selection within that band. This prevents a large new-term pool from overwhelming a small set of weak terms. Overdue reviews receive weights of at least 150, weak terms 80, learning 45, new 25, not-due review 12 and not-due mastered 1. Overdue weight increases with lateness. The previous three answered terms are excluded across sessions. A recent unresolved mistake is explicitly brought back after at least six intervening answers when the filters still permit it. If the remaining filtered pool cannot satisfy the cooldown, the session ends with an explanation instead of repeating immediately.

### Review schedule

The first correct response schedules a review after **10 minutes**. Passing a review at or after its due time advances to **1 day → 3 days → 7 days → 14 days → 30 days**, then repeats at 30 days. Early correct practice improves familiarity counts but does **not** advance the stage, postpone the due time or earn a successful spaced review. This prevents rapid clicking from simulating retention.

A wrong answer resets the correct streak, reduces the stage by two, schedules another review after **2 minutes**, and reduces the mastery score by at least 20 points (floored at zero). Due wrong answers also count as failed reviews. At stage zero, a passed due retry advances to one day. Mistake retries can appear before their due time for reinforcement, but these early successes do not advance spacing.

### What “gemeistert” means

All conditions must hold simultaneously:

- At least **5 correct learning answers** overall.
- At least **80% lifetime learning accuracy**.
- At least **2 correct answers in each direction**.
- At least **3 successful reviews performed when due**.
- Review stage at least **3** (the seven-day interval has been reached).
- At least **3 consecutive correct answers**, and all of the last **5 answers correct**.

Status is `new` until answered, `learning` while initially acquiring the term, `review` after two correct answers, and `mastered` only if every condition above holds. A subsequent wrong learning answer immediately returns a mastered term to review, a deliberately conservative policy. Requalification requires the evidence and recent-error rules again. A missed review alone does not erase mastery; it appears in the due count.

The 0–100 mastery evidence score combines correct-answer count (20), both direction counts (15 each), spaced successes (30), accuracy (10), and streak (10). It is an explanatory score, **not** the mastery threshold. Dashboard learned counts and percentage use the strict `mastered` status, never “answered correctly once,” and never just the score.

### Modes and statistics

- **Smart Learning:** full weighted scheduling and learning updates.
- **Freies Training / Random Practice:** uniformly random eligible targets; complete answer history and session/global answer statistics, but **no changes to progress, mastery or review scheduling**.
- **Schwache Begriffe:** terms with mistakes and either accuracy below 80% or correct streak below two.
- **Fällige Reviews:** only terms with a due timestamp at or before now.
- **Neue Begriffe:** only unanswered learning terms; terms leave this pool after their first learning answer.

Modes intersect with source, area, subsection and status filters. Sessions support 10/20/50/100 questions or 0 for endless, with manual stopping. Ending a filtered session early when it has no eligible terms is normal. Session summaries show actual counts, accuracy, newly mastered/lost mastery among practiced terms, and weakest/strongest practiced terms by mastery score.

Global accuracy and streaks include free practice. Per-term and section learning statistics exclude free practice, as labelled in the UI. A section's percentage is mastered terms / its unique terms, not answer accuracy; both are displayed. Because a pair can belong to multiple sections, section totals should not be summed to obtain the global total. `times_seen` is the number of answered learning questions; pending unanswered displays do not count. All question presentations are persisted separately in `questions`.

## SQLite schema

| Table | Purpose |
|---|---|
| `schema_version` | Initialization version marker |
| `sources` | Source filename, original title and subject |
| `sections` | Source ownership, section code/title, area extracted from code |
| `terms` | Exact original term/definition; SHA-256 pair ID and unique pair constraint |
| `term_sections` | Many-to-many membership so duplicate pairs share learning progress |
| `progress` | Status, answer counts, streak, evidence score, separate direction counts, successful/failed due reviews, interval stage, recent outcomes, review timestamps |
| `quiz_sessions` | Settings/filters, timestamps, totals, initial mastered set for summaries |
| `questions` | Persisted direction, choice tokens/text, private correct token and timestamps |
| `answer_history` | One immutable result per question, chosen/correct text, direction, response time, before/after state, session and term references |

Tables and indexes are created automatically. Foreign keys, WAL journaling, busy timeout, and transactional answers/imports are enabled. Timestamps are UTC Unix milliseconds and rendered in the browser's locale. Response time is server-observed elapsed time, including tab inactivity. Back up `data/learning.sqlite` after stopping the app so WAL writes have closed; keep source JSON files with the backup.

## REST API

| Method | Route | Input / result |
|---|---|---|
| GET | `/api/stats` | SQLite-derived global metrics |
| GET | `/api/sections` | Sources, sections and section learning statistics |
| POST | `/api/quiz/session` | `{mode, length, filters: {source, area, section, state}}` |
| GET | `/api/quiz/session?id=...` | Session / finished-session summary |
| GET | `/api/quiz/next?sessionId=...` | Existing pending question or newly selected question / completion |
| POST | `/api/quiz/answer` | `{sessionId, questionId, choiceToken}`; correctness and original pair after checking |
| POST | `/api/quiz/stop` | `{sessionId}`; persisted completion summary |
| GET | `/api/progress` | Optional `source,area,section,state,search,offset`; 50-row pages |
| GET | `/api/terms/{id}` | Per-term learning details and latest 30 answer-history entries |
| GET | `/api/review/due` | Due-only paginated terms; same filters |

Mode values: `smart`, `random`, `weak`, `due`, `new`. State filters: `all`, `weak`, `due`, `new`, `learning`, `review`, `mastered`. Section/source filters use IDs returned by `/api/sections`. Input errors use JSON `{error}` with an appropriate HTTP error status. The local learning library intentionally exposes the dataset; token handling prevents accidental answer leakage in the quiz response, not deliberate self-cheating by looking up a term.

## Tests

```powershell

```

Tests use independent in-memory or temporary databases, never your learning database. They validate every supplied pair in both directions for six unique choices and one correct answer; random direction/position coverage; duplicate import and exact wording; time-gated mastery; independent direction evidence; wrong-answer regression; priority weighting; token validation; cooldown; duplicate submission; filters; session completion; and free-practice isolation.

## Important limitations / improvements

- Semantic ambiguity cannot be proven absent solely from plain term/definition strings. Matching labels/definitions and normalized duplicate choices are excluded, but differently worded synonyms or overlapping definitions may still require dataset-owner review. Curated equivalence metadata would improve this without altering original wording. No external definitions are used.
- The schedule is a transparent conservative heuristic, not a clinically or empirically calibrated memory model. Adaptive individual intervals could be added after collecting sufficient usage data.
- The app is single-user and local. It has no authentication, cross-device sync or encrypted database.
- Imports are additive, not destructive synchronization. Future source revision tooling should explicitly reconcile changed pairs while preserving history.
- Random mode intentionally leaves learning progress unchanged, including on mistakes. Use Smart Learning / Review Due when measuring retention.
- The UI uses small dependency-free JavaScript modules rather than React/TypeScript; the backend remains the sole authority for all quiz and learning logic.
